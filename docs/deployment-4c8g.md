# 4CPU / 8GB 部署说明

当前程序可以在 4CPU、8GB 单实例运行。服务、预计算表和 4,096 项精确结果缓存的内存占用较小；玩家模型默认限制 10,000 名玩家和每人 256 项去重窗口，避免无界增长。线上必须复用单个 Calculator/Tracker，而不是按请求创建。

按 Apple M1 开发机基准，NLH 翻牌 5,000 样本约 19ms，PLO5 1,000 样本约 18ms，PLO6 1,000 样本约 27ms。4 核可承载预期 15～30 次/秒的混合决策平均负载，但不能保证 100～150 次/秒的持续 PLO6 峰值；低性能 x86 云 CPU 还应预留更大余量。

建议初始设置：单实例、GOMAXPROCS=4，HTTP 决策超时 100～150ms，重计算并发上限 3，PLO6 保持默认 1,500 样本；CPU 连续超过 70% 时减少采样或扩容。所有日志写 stdout，由宿主机轮转并限制 3～7 天本地留存。上线前在目标机器用真实玩法比例压测 30 分钟，验收 p95、p99、超时率、CPU、RSS 与日志磁盘增长。

HTTP 已接入真实状态、equity、策略、人格和玩家模型。默认 `max_concurrent: 3` 限制 CPU 计算并发，状态最多保留 50,000 手。启用 `apply_think_time` 时等待不占计算槽，但会占用 HTTP goroutine；现有 15 秒写超时覆盖内置最长思考时间。
