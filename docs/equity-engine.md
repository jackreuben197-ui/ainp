# 基础牌力与胜率引擎

第 2 阶段已完成独立的 NLH、短牌、PLO4、PLO5 和 PLO6 牌力与胜率核心，代码位于 internal/poker 和 internal/equity。它只使用当前可见牌、已知弃牌和配置的对手手牌，不读取未发牌序、真人隐藏底牌或 RNG 内部状态。

## 牌编码与牌型

协议牌使用两字符格式：点数 2-9/T/J/Q/K/A，花色 s/h/c/d，例如 AsKd。Card 内部使用 0..51 紧凑编码。

Evaluate 接受 5～7 张互不重复的牌，返回：

- High Card 到 Royal Flush 的牌型。
- 可直接比较的 Score。
- 组成结果的 BestFive。

实现会从最多 7 张牌中选择最佳五张。测试穷举全部 2,598,960 种五张牌组合，其十类牌型数量与标准组合数学结果完全一致。

短牌支持 36 张牌和 A-6-7-8-9 顺子。SHORT_DECK 对应项目现有 SixPlus 规则：同花大于葫芦、三条大于顺子；SHORT_DECK_FIXED 保持顺子大于三条，但同花仍大于葫芦。测试同时穷举全部 376,992 种短牌五张组合。

PLO4/PLO5/PLO6 在 EvaluateOmaha 和全部 Equity 路径中强制恰好选择两张手牌与三张公共牌，不能把五张公共牌直接当作成牌。三者规则相同，区别仅是每名玩家持有 4、5、6 张手牌。

## Equity API

Calculator.Calculate 接收：英雄两张牌、0/3/4/5 张公共牌、1～8 个对手、已知死牌、算法、采样数、随机种子和精确枚举上限。

每个对手传两张牌表示已知手牌，传空切片表示从剩余牌中随机发牌。Result 返回 win/tie/loss probability、多人平分后的 equity、样本计数、算法、95% 误差范围、估算的精确组合数、耗时、缓存和完成状态。

算法：

| 场景                             | Auto 默认行为        |
| -------------------------------- | -------------------- |
| NLH 翻牌前，单个随机对手，无死牌 | 169 类嵌入式查表     |
| 估算结果不超过 5,000 种          | 精确枚举             |
| 更大搜索空间                     | 5,000 次 Monte Carlo |

PLO4 默认 3,000 次模拟，PLO5 默认 2,000 次，PLO6 默认 1,500 次；它们每次需要评估 C(n,2) 组手牌组合。调用方可以显式覆盖 Samples。

显式 exact 超过 MaxExactOutcomes 会返回 ErrExactTooLarge，不会意外占满 CPU。Monte Carlo 使用请求种子，可确定性回放；种子为零时由当前时间生成。计算每 256 个结果检查 context，取消或超时会返回已完成的部分统计并标记 Completed=false。

## 翻牌前表

preflop_table_generated.go 包含 169 类起手牌对单个随机对手的数据，每类由固定种子的 20,000 次模拟生成。cmd/preflopgen 可重复生成该文件。该表不能用于已知对手 Range、多对手或存在死牌的场景，这些场景自动使用 Monte Carlo。

## 缓存

精确结果使用每个 Calculator 实例独立的 4,096 项并发安全有界缓存。缓存键规范化英雄牌、公共牌、死牌和对手牌，Monte Carlo 不缓存，避免混淆不同随机种子和采样数。

## 当前基准

测试机器：Apple M1，Go 1.23.4。

| 基准                                  |      耗时 |
| ------------------------------------- | --------: |
| 翻牌、单挑、5,000 次 Monte Carlo      | 约 21.8ms |
| 河牌、单个随机对手、990 种精确枚举    | 约 2.85ms |
| 翻牌前单挑查表                        | 约 0.39µs |
| 短牌翻牌、单挑、5,000 次 Monte Carlo  | 约 16.8ms |
| PLO4 翻牌、单挑、1,000 次 Monte Carlo | 约 10.9ms |
| PLO5 翻牌、单挑、1,000 次 Monte Carlo | 约 17.9ms |
| PLO6 翻牌、单挑、1,000 次 Monte Carlo | 约 27.0ms |

PLO6 每个玩家需比较 15 组手牌组合，PLO5 为 10 组，因此同样样本数下开发机实测约慢 51%，但没有新的算法或协议复杂度。默认降低为 1,500 次采样，以限制延迟。这些数字是开发机基准，不是生产 SLA。多人底池耗时会随对手数量增加；线上仍需设置请求超时、并发上限并复用 Calculator 实例。

## 未包含范围

- 对手 Range 加权；当前未知对手按剩余牌均匀随机。
- 两次发牌以及短牌与奥马哈组合等特殊桌型。
- 按对手行动动态收窄的 Range Equity；当前 HTTP provider 使用均匀未知牌或合法公开牌。
- 分布式缓存和跨实例任务协调。

后续增强不应修改当前牌型比较和基础概率语义。
